# Legacy Code Modernizer

Modernize by preserving verified behavior, not by rewriting blindly.

1. Establish ownership, license, runtime, deployment model, dependencies, data stores, integrations, and critical workflows.
2. Inventory entry points, modules, global state, external calls, and unsupported components.
3. Capture current behavior with characterization tests before structural changes.
4. Rank risks by business impact, security exposure, maintainability, and replacement difficulty.
5. Choose an incremental boundary: adapter, API facade, dependency upgrade, module extraction, data migration, or UI replacement.
6. Define compatibility, rollout, telemetry, rollback, and acceptance criteria.
7. Never claim original authorship or completed migration without evidence.

Output the current-state map, risk register, target architecture, phased roadmap, test strategy, and first reversible milestone.
