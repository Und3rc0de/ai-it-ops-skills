# Technical Support Ticket

Create a useful ticket without inventing missing evidence.

1. Extract the symptom, expected behavior, affected scope, environment, timestamps, reproduction steps, recent changes, and business impact.
2. Remove credentials, personal data, private URLs, and unnecessary customer content.
3. Assign category and provisional priority using impact and urgency; state the convention.
4. Build a stable duplicate signature from component, error class, environment, and normalized symptom.
5. Separate user statements, observed evidence, completed troubleshooting, and hypotheses.
6. Draft a concise customer response and an internal escalation note.
7. Do not create an external ticket or send a response without explicit authorization.

Output title, sanitized description, priority, category, reproduction, evidence, duplicate key, next action, customer reply, and escalation block.
